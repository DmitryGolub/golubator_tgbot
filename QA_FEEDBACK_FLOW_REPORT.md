# QA Feedback Flow Report

Дата проверки: 2026-03-18

Репозиторий: `https://github.com/DmitryGolub/golubator_tgbot`

Автотесты: `tests/test_feedback_flow_qa.py`

## Что было проверено

1. Student feedback через `/survey <id_созвона>` от старта до сохранения комментария.
2. Mentor feedback через меню ментора и callback-сценарий выбора созвона.
3. Наличие пользовательской точки входа в mentor feedback.
4. Невозможность пропустить обязательные шаги через UI и callback flow.
5. Сохранение текстовых комментариев в обоих сценариях.
6. Привязка student и mentor feedback к выбранному `call_id`.
7. Выбор кандидатов для mentor feedback только среди реально завершённых созвонов.

## Что работает корректно

- Student feedback проходит happy-path без ошибок:
  старт по `/survey <id_созвона>`, выбор длительности, три обязательные оценки, текстовый комментарий и финальное сохранение.
- В student flow обязательные шаги нельзя пропустить кнопками:
  `survey_skip` появляется только на последнем, необязательном шаге с комментарием.
- Student flow защищён от устаревших callback-кнопок:
  кнопка с чужим `call_id` отклоняется текстом `Эта кнопка больше неактуальна.`.
- Mentor feedback доступен из меню ментора через `mentor_feedback_start` и проходит happy-path без ошибок:
  выбор созвона, статус, длительность, мотивация, стадия нейромутации, комментарий, сохранение.
- В mentor flow невалидный ввод на обязательном числовом шаге не продвигает сценарий дальше.
- Оба сценария сохраняют правильную привязку к выбранному созвону:
  в service layer уходит именно тот `call_id`, который был выбран пользователем.

## Найденные проблемы

1. Mentor feedback можно открыть для созвона, который ещё не завершён фактически.
   Сейчас `src/bot/handlers/mentor_feedback.py::_is_completed_meeting()` считает созвон "завершённым", если `scheduled_at <= now`.
   Из-за этого `src/bot/handlers/mentor_feedback.py::_get_feedback_candidates()` отдаёт в список фидбека встречи с `completed_at = NULL`, если их запланированное время уже прошло.
   Что нужно чинить:
   использовать явный признак завершения (`meeting.completed_at is not None`) вместо проверки только по `scheduled_at`.
   Иначе ментор может оставить фидбек до фактического завершения созвона, что ломает бизнес-правило привязки фидбека к реально завершённой встрече.

## Результат прогона

## Итог

Целевой feedback flow в happy-path сейчас проходим и для ученика, и для ментора.

Главный подтверждённый дефект один:
mentor feedback открывается не только для реально завершённых созвонов, а для любых встреч, чьё `scheduled_at` уже в прошлом.

Итоговая оценка:
основной пользовательский сценарий работает, но выбор кандидатов для mentor feedback нужно исправить в `src/bot/handlers/mentor_feedback.py`.
